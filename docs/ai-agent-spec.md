# MyBlog AI Agent 功能规格说明书（Spec）

> 版本：v1.0・日期：2026-10-02・状态：待评审

## 1. 项目背景与目标

### 1.1 一句话定位

为 MyBlog 博客站点的注册用户提供「内置 AI 对话助手」：用户可以在站内与 AI 对话，对话时可携带站内文章作为上下文提问，也可自由闲聊；每个用户的会话记录独立保存，可随时回到任意历史对话继续聊。

### 1.2 业务目标



* 提升站点停留时长与用户粘性，把「读文章」升级为「和文章对话」。

* 复用站内文章资产，形成差异化能力（其他博客没有的站内 AI 问答）。

### 1.3 成功指标



* 北极星指标：Agent 栏目 DAU / 站点总 DAU ≥ 15%。

* 辅助指标：人均会话数 ≥ 2；会话中引用文章的比例 ≥ 30%；对话首响应延迟 P95 < 5s（流式首 token < 2s）。

### 1.4 约束



* 技术栈与现有项目一致：后端 Go (Gin, GORM, DDD 四层) + 前端 Vue3 (Vite, Pinia, Element Plus, i18n) + MySQL。

* 新功能以独立 BC（`agent`）接入，不破坏现有 DDD 分层与 router 注册方式。

* LLM 使用阿里云百炼（DashScope）OpenAI 兼容接口，模型默认 `qwen-max`，API Key 通过配置 / 环境变量注入，不写入代码与数据库。

* 不引入重量级 AI 框架（LangChain 等），直接用 HTTP + SSE 实现，保持依赖最小。

## 2. 用户分析

### 2.1 用户画像



* **访客（未登录）**：浏览文章为主，可在 Agent 页面看到引导登录提示。

* **注册用户（核心）**：登录后使用 Agent 对话；有自己的会话历史列表。

* **管理员**：与普通用户功能一致；可查看系统调用统计（Phase 2 可选）。

### 2.2 核心使用场景



1. **带文章提问**：用户读某篇文章后，进入 Agent，选择该文章，向 AI 提出「总结这篇文章的核心论点」等问题。

2. **自由对话**：不选文章，直接与 AI 闲聊 / 咨询。

3. **恢复历史**：用户从左侧会话列表点击某条历史记录，回到当时的对话上下文继续提问。

### 3.2 用户故事与验收标准

#### US-1：导航入口

> 作为 访客，我想要 在导航栏看到 Agent 栏目，以便 快速进入 AI 对话。



* Given 我访问站点任意页面

* When 我查看顶部导航栏

* Then 导航栏出现「AI Agent」菜单项，与首页 / 论坛等同级

* And 点击后跳转到 `/agent` 页面

#### US-2：登录校验

> 作为 访客，我想要 使用 Agent，以便 与 AI 对话。



* Given 我未登录且访问 `/agent`

* When 页面加载

* Then 显示登录引导（复用现有 AuthPopover），不展示会话列表

#### US-3：自由对话（不选文章）

> 作为 注册用户，我想要 不选任何文章直接与 AI 对话，以便 快速提问。



* Given 我已登录且进入 `/agent`

* When 我在输入框输入问题并发送

* Then 消息进入对话区，AI 以流式方式逐字返回

* And 不注入任何站内文章上下文

#### US-4：选择文章提问

> 作为 注册用户，我想要 在对话中附带选中的站内文章，以便 就文章内容提问。



* Given 我已登录且进入 `/agent`

* When 我点击「选择文章」，从文章选择器勾选 1\~N 篇文章（默认上限 5 篇），发送提问

* Then 后端将该批文章标题 + 正文（截断至每篇上限）注入模型上下文

* And AI 的回答基于所选文章内容

#### US-5：会话记忆（多轮）

> 作为 注册用户，我想要 AI 记住当前对话上文，以便 连续追问。



* Given 我处于某个会话中

* When 我连续发送多条消息

* Then 每条消息都携带该会话全部历史消息作为上下文

* And 模型能引用前文内容作答

#### US-6：会话历史列表

> 作为 注册用户，我想要 左侧看到自己的历史会话，以便 回到过去的对话。



* Given 我已登录且进入 `/agent`

* Then 页面左侧展示我的全部会话（标题 = 首条用户消息摘要，按更新时间倒序）

* And 仅展示我自己的会话（user\_id 隔离）

* And 提供「新建会话」「删除会话」操作

#### US-7：恢复会话

> 作为 注册用户，我想要 点击历史会话回到原对话，以便 继续之前的问题。



* Given 左侧列表存在历史会话

* When 我点击某条记录

* Then 右侧加载该会话全部消息（含文章引用标识），并可继续发送消息

* And 后续发送仍携带该会话完整历史

#### US-8：会话自动命名

> 作为 注册用户，我想要 会话有可读标题，以便 在列表中识别。



* Given 我发送了首条消息

* Then 系统以首条用户消息的前 30 字作为会话标题（可由 Phase 2 升级为 LLM 摘要）

### 3.3 记忆体系定义（重要）

「记忆」在本需求中拆为三层，逐层实现：



| 层级 | 名称     | 机制             | 实现                                                                         | 版本               |
| -- | ------ | -------------- | -------------------------------------------------------------------------- | ---------------- |
| L1 | 会话记忆   | 模型感知当前会话全部历史消息 | MySQL `agent_messages` 表，组装 messages 数组注入                                  | MVP              |
| L2 | 会话历史   | 跨会话恢复、按用户隔离    | MySQL `agent_conversations` + `agent_messages`，左侧列表                        | MVP              |
| L3 | 用户画像记忆 | 跨会话记住用户偏好 / 事实 | `agent_memories` 表存结构化偏好，新会话注入 system prompt（基础版：从对话提取关键词级画像）；Phase 2 可向量化 | MVP (基础)/P2 (增强) |

## 4. 非功能需求



| 类别  | 要求                                                                                  |
| --- | ----------------------------------------------------------------------------------- |
| 性能  | 首 token 流式返回 < 2s（P95）；普通接口 P95 < 500ms                                             |
| 安全  | 所有 Agent 接口走 JWT（privateGroup）；user\_id 从 claims 取，禁止越权访问他人会话；LLM Key 存服务端配置，不出现在前端 |
| 数据  | 文章正文注入前截断（每篇 ≤ 8000 字符），控制 token 成本                                                 |
| 并发  | 同一用户并发会话数建议 ≤ 3（可选限流，Phase 2）                                                       |
| 兼容  | 支持 Chrome/Firefox/Safari 最新两版；移动端可用（左侧列表可收起）                                        |
| 国际化 | 菜单与页面文案接入现有 i18n（zh-CN /en/zh-TW）                                                   |
| 流式  | 使用 SSE（`text/event-stream`），前端 fetch 流式解析，支持中断（AbortController）                     |

## 5. MVP 范围

### ✅ 包含（Phase 1）



* 导航栏目 + `/agent` 路由（登录可访问，未登录引导）

* 自由对话（不选文章）+ 流式输出

* 选择文章（多选，复用现有文章搜索 / 分类接口）注入上下文

* 会话级记忆（L1）+ 会话历史（L2）+ 基础用户画像记忆（L3 基础版）

* 左侧会话列表（新建 / 删除 / 点击恢复）

* i18n 三语言

* 单元测试（domain/application）+ 关键接口冒烟测试

### ❌ 不包含（Phase 1 明确不做）



* 自动语义召回文章（用户不选文章时，Agent 不自动检索文章库）

* 向量数据库

* 管理员统计面板

* 会话重命名（手动改标题）、消息编辑 / 删除、分享

* 多模型选择、温度等参数面板

### 📋 后续版本（Phase 2）



* 向量数据库（docker）：文章语义索引 + 自动召回 + 记忆向量化

* LLM 摘要自动命名会话

* 对话限流、用量统计

* 会话搜索

## 6. 数据模型设计（v1）

### 6.1 表结构

**agent\_conversations 会话表**



| 字段                                      | 类型           | 说明                 |
| --------------------------------------- | ------------ | ------------------ |
| id                                      | BIGINT PK    | 主键                 |
| user\_id                                | BIGINT       | 所属用户（索引）           |
| uuid                                    | CHAR(36)     | 会话 UUID（对外标识）      |
| title                                   | VARCHAR(100) | 会话标题（首条消息截取）       |
| summary                                 | TEXT         | 会话摘要（L3 画像提取来源，可空） |

**agent\_messages 消息表**



| 字段               | 类型          | 说明                         |
| ---------------- | ----------- | -------------------------- |
| id               | BIGINT PK   | 主键                         |
| conversation\_id | BIGINT      | 所属会话（索引）                   |
| role             | VARCHAR(10) | user / assistant           |
| content          | TEXT        | 消息正文                       |
| article\_ids     | JSON        | 本条消息携带的文章 ID 列表（user 消息有效） |
| tokens           | INT         | 该条消息消耗 token（统计用，可空）       |
| created\_at      | -           | MODEL 基类                   |

**agent\_memories 用户画像记忆表（L3 基础版）**



| 字段                        | 类型           | 说明                  |
| ------------------------- | ------------ | ------------------- |
| id                        | BIGINT PK    | 主键                  |
| user\_id                  | BIGINT       | 所属用户（索引）            |
| content                   | VARCHAR(500) | 记忆条目（如「用户偏好 Go 语言」） |


## 7. API 设计（v1）

全部接口位于 `privateGroup`（JWT 必需），前缀 `/agent`。



| 方法     | 路径                                | 说明           | 请求 / 响应要点                                                             |
| ------ | --------------------------------- | ------------ | --------------------------------------------------------------------- |
| POST   | /agent/conversations              | 新建会话         | body: {} → 返回 {id, uuid, title}                                       |
| GET    | /agent/conversations              | 会话列表         | → \[{id, uuid, title, updated\_at}]                                   |
| GET    | /agent/conversations/:id/messages | 会话消息         | → \[{role, content, article\_ids, created\_at}]                       |
| DELETE | /agent/conversations/:id          | 删除会话（级联删消息）  | → ok                                                                  |
| POST   | /agent/chat                       | 发送消息（SSE 流式） | body: {conversation\_id?, message, article\_ids?} → text/event-stream |

**SSE 协议**：`data: {"delta": "..."}` 逐块；结束事件 `data: [DONE]`；错误事件 `data: {"error": "..."}`。

> 前端聊天每发一条消息即持久化该条 user 消息（role=user）；assistant 消息在流式结束后落库。若 conversation_id 为空则先自动建会话。

## 9. 向量数据库决策（回答专项问题）

**结论：MVP（Phase 1）不需要引入向量数据库，5 项需求全部可用 MySQL + LLM API 实现；向量数据库作为 Phase 2 可选增强，用 docker 一条命令拉起。**

理由（逐条对应需求）：



| 需求           | 为什么不需要向量库                                           |
| ------------ | --------------------------------------------------- |
| 1. 导航栏目      | 纯前端路由 / 菜单，与存储无关                                    |
| 2. Agent 带记忆 | 记忆 = 会话历史 + 多轮上下文 + 画像条目，均为结构化数据，MySQL 表即可承载        |
| 3. 选择文章提问    | 用户**主动选择**文章 → 拿文章 ID 从 MySQL 读正文，拼接进 prompt，无需语义检索 |
| 4. 不选文章      | 就是普通对话，直接调 LLM                                      |
| 5. 左侧使用记录    | 会话 / 消息按 user\_id 查询，MySQL 索引即可，量级（个人博客）远未到需要向量库    |

向量数据库真正有价值、但**不是本需求硬性要求**的场景：



* 用户不选文章时，Agent 自动从全站文章库「语义召回」相关内容（需要文章向量索引 + 检索）。

* L3 长期记忆按语义相似度召回（而非简单注入全部条目）。

* 这两点已列入 Phase 2（F11/F12），届时 `docker run` 拉取轻量向量库（推荐 **Qdrant** 或 **pgvector**，均为单容器部署），并在 domain 层预留 `ArticleRetriever` / `MemoryRetriever` 端口，Phase 2 只实现端口不重构主流程。

## 10. 风险与依赖



| 风险 / 依赖                       | 等级    | 缓解                                                |
| ----------------------------- | ----- | ------------------------------------------------- |
| 外部依赖：DashScope API 稳定性 / 限流   | 中     | 服务端错误兜底文案；流式中断可重试；Key 走配置                         |
| LLM 成本                        | 中     | 文章正文截断 + 历史消息窗口裁剪（保留最近 20 条）                      |
| SSE 与现有前端 request 封装（axios）兼容 | 中     | 流式接口单独用 fetch 实现，不走 axios 拦截器                     |
| 长对话上下文膨胀                      | 低     | 滑动窗口裁剪 + summary 降级                               |
| 越权访问他人会话                      | 高（安全） | 所有查询强制带 user\_id 条件，handler 层从 claims 取 id，不经前端参数 |

## 11. 关键假设（待用户确认项）



1. Agent 仅登录用户可用（访客引导登录）。

2. 模型默认 `qwen-max`（用户已验证 Key 可用），可在 `config.yaml` 切换。

3. 单条消息最多携带 5 篇文章。

4. 会话标题取首条消息前 30 字（不做 LLM 摘要）。

5. Phase 1 不做自动文章召回（用户不选文章即纯自由对话）。

## 12. 附录：技术要点



* 后端新增 BC 目录：`server/internal/{domain,application,interface/http/handler}/agent` + `server/internal/infrastructure/llm`（DashScope provider）。

* Go 侧调用 DashScope：`POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`，`stream: true`，用 `net/http` 直连 + `bufio.Scanner` 解析 SSE 行，经 gin `c.Stream` 转发前端；不新增第三方 SDK 依赖。

* 前端文章选择器复用现有接口：`GET /article/search`（或 category/tags），由前端搜索后勾选。

* 前端新增：`web/src/views/web/agent/index.vue`、`web/src/api/agent.ts`、`web/src/stores/agent.ts`、`web/src/components/agent/ArticlePicker.vue`、`web/src/components/agent/MessageList.vue`。
